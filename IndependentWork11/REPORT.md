## 3. Відповіді на контрольні запитання

1. **Чому структура `Dictionary<string, HashSet<int>>` добре підходить для реалізації інвертованого індексу?**  
   `Dictionary` дозволяє знайти слово за $O(1)$, а `HashSet` зберігає унікальні ID документів та підтримує швидкі математичні операції над множинами (`IntersectWith`, `UnionWith`) за $O(1)$ для кожного елемента.

2. **Які переваги `HashSet<T>` дає під час обчислення AND/OR-пошуку за кількома словами?**  
   Для операції **AND** використовується метод `IntersectWith()`, який за залишає лише спільні елементи. Для **OR** використовується `UnionWith()`, що миттєво об'єднує множини без дублювання елементів.

3. **Чому під час вимірювання продуктивності важливо однаково нормалізувати текст для лінійного пошуку та пошуку через індекс?**  
   Якщо методи нормалізації (токенізація, видалення пунктуації, регістр) відрізняються, то лінійний та індексований пошук повернуть різну кількість результатів, що робить порівняння часу некоректним.

4. **Які обмеження має проста реалізація інвертованого індексу без ранжування, стемінгу та підтримки фраз?**  
   - Відсутність ранжування (TF-IDF): релевантні результати не сортуються завагою.
   - Відсутність стемінгу: пошук "programming" не знайде слово "programmers".
   - Відсутність точного пошуку фраз: не можна знайти словосполучення з урахуванням порядку слів.

## 4. Висновок
Інвертований індекс забезпечує прискорення пошуку в тисячі разів порівняно з лінійним обходом, оскільки замість токенізації всього вмісту документів при кожному запиті ($O(N \cdot M)$) виконується миттєва вибірка готових ID за $O(1)$.
