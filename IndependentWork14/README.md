## 1. Мета роботи
Реалізувати власну узагальнену політику повторних спроб з експоненціальною затримкою та jitter.

## 2. Хід виконання роботи
Створено проєкт `IndependentWork14`, як вказано в умові самостійної №15. Клас `RetryPolicy` має поля `_maxRetries`, `_initialDelay`, `_jitterFactor`, конструктор із перевіркою параметрів і метод `Execute<T>`. Завдяки `Func<T>` політика підходить для різних типів результату.

Затримка перед повтором із номером r (відлік із нуля) обчислюється за формулою:

```text
delay = initialDelay * 2^r * (1 + random * jitterFactor * 2 - jitterFactor)
```

При `initialDelay = 40 мс` і `jitterFactor = 0.2` номінальні затримки — 40, 80, 160 мс, допустимі діапазони — 32–48, 64–96, 128–192 мс. Випадковий множник генерується через `Random.Shared`. Перед очікуванням виводяться номер повтору, час і причина помилки. Затримка обмежена верхньою межею `Thread.Sleep`, щоб велике значення не переповнило допустимий діапазон.

`maxRetries` — число повторів після першого виклику. Отже, `maxRetries = 2` дозволяє до 3 спроб. Значення 0 вимикає повтори. `shouldRetry` вибирає винятки для повторення; без нього повторюються звичайні винятки. `OperationCanceledException` не повторюється. Після вичерпання спроб чи відмови предиката початковий виняток передається викликачеві.

Неприпустимі від’ємні повтори й затримка, jitter поза [0; 1], NaN/нескінченність та null-операція. Реалізація синхронна: `Thread.Sleep` блокує потік, що допустимо для цієї навчальної демонстрації.

## 3. Демонстрація
1. **Тимчасова IOException:** перші дві спроби читання файлу неуспішні, третя повертає рядок. У фактичному запуску затримки становили 43.4 та 94.8 мс і потрапили у відповідні діапазони.
2. **Постійна TimeoutException:** політика з двома повторами викликає операцію тричі. Після цього виняток перехоплюється в Main. Фактичні затримки — 31.4 і 58.6 мс для початкової затримки 30 мс.
3. **Помилка вхідних даних:** ArgumentException не відповідає умові `ex is IOException`, тому виконується лише одна спроба.

```text
Читання файлу, спроба 1
Повтор 1/3 через 43,4 мс. Причина: Файл тимчасово зайнятий.
Читання файлу, спроба 2
Повтор 2/3 через 94,8 мс. Причина: Файл тимчасово зайнятий.
Читання файлу, спроба 3
Файл прочитано.
```

Через jitter числа при повторному запуску зміняться. Зазначений час — запланована затримка; фактичне очікування також залежить від планувальника ОС.

## 4. Відповіді на контрольні запитання
1. **Навіщо exponential backoff?** Збільшення пауз зменшує інтенсивність звернень під час збою й дає сервісу час відновитися.
2. **Навіщо jitter?** Випадкове відхилення розводить повтори різних клієнтів у часі, зменшуючи одночасні хвилі навантаження.
3. **Навіщо shouldRetry?** Для відділення тимчасових помилок від постійних. Помилку валідації повтор зазвичай не виправляє.
4. **Чим небезпечні необмежені повтори?** Вони можуть нескінченно блокувати роботу, витрачати ресурси й посилювати перевантаження сервісу. Потрібні обмеження спроб, затримки та, за потреби, загальний ліміт часу.
