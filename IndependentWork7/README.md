## 1. Мета роботи
Розробити узагальнений клас кешу з обмеженою ємністю та політикою FIFO, а також написати юніт-тести для перевірки його функціональності.

---

## 2. Теоретичні відомості
* **Узагальнені типи (Generics):** дозволяють використовувати один клас для різних типів ключів і значень зі збереженням перевірки типів під час компіляції.
* **FIFO (First In, First Out):** при переповненні видаляється елемент, який був доданий найраніше. Читання значення не змінює порядок видалення.
* **Dictionary<TKey, TValue>:** зберігає пари ключ–значення та забезпечує пошук за ключем у середньому за O(1).
* **Queue<TKey>:** зберігає порядок додавання ключів. Методи `Enqueue` і `Dequeue` дозволяють додати ключ у кінець черги та отримати найстаріший ключ.

## 3. Хід виконання роботи
1. Створено консольний проєкт `IndependentWork7` та тестовий проєкт `IndependentWork7.Tests` із посиланням на основний проєкт. Назви відповідають умові, хоча номер самостійної роботи — №8.
2. Реалізовано клас `Cache<TKey, TValue>` із приватними полями `_capacity`, `_cache` та `_keysOrder`. Обмеження `where TKey : notnull` відповідає вимозі словника до типу ключа.
3. Конструктор перевіряє додатну ємність. Метод `Add` при переповненні видаляє найстаріший ключ із черги та словника. Повторне додавання наявного ключа оновлює значення без зміни кількості та початкового порядку FIFO.
4. Метод `Get` використовує `TryGetValue` та викидає `KeyNotFoundException`, якщо ключ відсутній. Додано метод `ContainsKey` і властивість `Count` лише для читання.
5. Написано тести xUnit для додавання, отримання, відсутнього ключа, перевірки наявності ключа та кількості елементів. Окремо перевіряються FIFO після читання, багаторазове переповнення, оновлення ключа, ємність 1 і некоректна ємність.
6. У `Main` продемонстровано `Cache<string, decimal>` із ємністю 3: ключем є назва товару, значенням — ціна у гривнях. Використано українську локалізацію `uk-UA`. Після додавання монітора найстаріший товар «Ноутбук» видаляється, а кількість елементів залишається рівною 3. Оновлення ціни смартфона не додає нового елемента. Виняток під час отримання ноутбука перехоплюється і виводиться як очікуваний результат.

## 4. Відповіді на контрольні запитання

1. **Які переваги надає Cache<TKey, TValue> порівняно з окремими неузагальненими реалізаціями кешу?**  
   Один клас працює з різними типами даних без дублювання коду. Компілятор перевіряє типи ключів і значень, тому не потрібні ручні приведення від `object`.

2. **Чому для реалізації FIFO зручно поєднувати Dictionary<TKey, TValue> з Queue<TKey> або LinkedList<TKey>?**  
   Словник забезпечує швидкий доступ за ключем, а черга або зв’язний список зберігають порядок додавання. Для FIFO достатньо черги: найстаріший ключ отримується через `Dequeue`, після чого відповідна пара видаляється зі словника.

3. **Коли Get повинен викидати KeyNotFoundException, а коли доцільніше використовувати TryGetValue?**  
   `Get` викидає виняток, коли запитаного ключа немає, зокрема після його витіснення. Підхід `TryGetValue` зручний, якщо відсутність даних є звичайною ситуацією і викликач хоче обробити її без винятку. У цій роботі `Get` використовує `TryGetValue` всередині та явно створює виняток відповідно до умови.

4. **Які тести є критично важливими для перевірки політики витіснення?**  
   Потрібно перевірити видалення саме найстарішого елемента, збереження інших значень, незмінність FIFO після читання та правильну роботу після кількох переповнень. Також важливі перевірки ємності 1, незмінної кількості після переповнення та оновлення наявного ключа без порушення черги.
