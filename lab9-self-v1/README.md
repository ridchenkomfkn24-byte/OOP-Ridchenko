## 1. Мета роботи
Закріпити використання делегатів і лямбда-виразів для створення узагальнених утиліт обробки колекцій.

## 2. Хід виконання роботи
Створено проєкт `lab9-self-v1`, назва якого відповідає шаблону з умови. Номер роботи — №10. Клас `CollectionUtils` містить чотири методи, реалізовані циклами без виклику відповідних LINQ-операторів:

| Метод | Делегат | Призначення | Час / додаткова пам’ять |
|---|---|---|---|
| Map | Func<TSource, TResult> | Перетворити кожний елемент | O(n) / O(n) |
| MaxBy | Func<T, TKey> | Знайти елемент із найбільшим ключем | O(n) / O(1) |
| Filter | Predicate<T> | Відібрати потрібні елементи | O(n) / O(k) |
| ForEach | Action<T> | Виконати дію для кожного елемента | O(n) / O(1) |

Оцінки наведено для делегатів сталої вартості; k — кількість відібраних елементів. Для порожньої колекції `MaxBy` викидає `InvalidOperationException`; при однакових найбільших ключах повертає перший елемент. Аргументи перевіряються на null. Кожен метод продемонстровано на `List<int>`, `List<string>` і `List<Product>`.

## 3. Відповіді та порівняння з LINQ
1. **Навіщо потрібні делегати?** Вони передають поведінку як параметр. Алгоритм обходу залишається один, а умову, перетворення чи дію можна змінювати без його переписування.
2. **Як лямбда-вирази спрощують виклик?** Запис `p => p.Price` замінює окремий метод для отримання ціни. Логіка видно безпосередньо біля виклику.
3. **Порівняння з LINQ.** `Map` відповідає `Select`, `Filter` — `Where`, `MaxBy` — однойменному оператору. У нашій реалізації Map і Filter одразу створюють списки; Select і Where для LINQ to Objects виконуються відкладено. Власний MaxBy завжди викидає виняток на порожній колекції; LINQ MaxBy для nullable/посилального типу може повертати null. Узагальненого LINQ-оператора ForEach для IEnumerable немає: зазвичай використовують foreach; метод List.ForEach працює лише зі списком.
4. **Різниця Func, Action і Predicate.** Func приймає аргументи та повертає результат; Action виконує дію без результату; Predicate<T> перевіряє елемент і повертає bool.
5. **Переваги generic-методів із лямбдами.** Один алгоритм працює з різними типами зі збереженням перевірки типів під час компіляції. Лямбда уточнює дію для конкретного виклику.
6. **Коли реалізовувати власні утиліти?** Для вивчення алгоритмів або спеціальної поведінки, якої немає у стандартних операторах. Для звичайних виробничих задач доцільно використовувати перевірені оператори LINQ.
