## 2. Аналіз відкритих проєктів
Наведені пояснення вибору колекцій і складності є аналізом переглянутого коду. Джерела перевірено 04.11.2026.

### Dictionary: LINQ ToDictionary у .NET Runtime
[Файл ToCollection.cs, метод ToDictionary](https://github.com/dotnet/runtime/blob/main/src/libraries/System.Linq/src/System/Linq/ToCollection.cs).

Метод перетворює послідовність на словник: обчислює ключ через `keySelector` та додає пару через `Add`. Словник дає пошук за ключем у середньому за O(1), тоді як у списку довелося б перебирати елементи. Побудова для n елементів займає в середньому O(n). Повторні ключі спричиняють виняток. Параметр `IEqualityComparer<TKey>` визначає правила рівності; без нього використовується стандартний порівнювач.

### HashSet: LINQ Distinct у .NET Runtime
[Файл Distinct.cs, клас DistinctIterator](https://github.com/dotnet/runtime/blob/main/src/libraries/System.Linq/src/System/Linq/Distinct.cs).

Ітератор зберігає вже побачені значення в `HashSet<TSource>` і повертає елемент лише тоді, коли `Add` успішний. Множина автоматично відкидає дублікати. Для списку кожна перевірка наявності потребувала б O(n). Додавання до множини займає в середньому O(1), повний перебір — у середньому O(n). Переданий `IEqualityComparer<TSource>` визначає, які елементи вважаються однаковими.

### Dictionary + HashSet: граф у Entity Framework Core
[Файл Multigraph.cs, клас Multigraph](https://github.com/dotnet/efcore/blob/main/src/Shared/Multigraph.cs).

У `_vertices` типу `HashSet<TVertex>` зберігаються унікальні вершини, а словники `_successorMap` та `_predecessorMap` пов’язують вершини з вихідними та вхідними зв’язками. Це дає швидкий доступ до сусідів без перегляду всіх ребер. Перевірка вершини та доступ за ключем займають у середньому O(1); перебір сусідів — O(k), де k — їхня кількість. Колекції використовують стандартну рівність ключів. Необов’язковий `IComparer<TVertex>` задає додатковий порядок сортування, а не хешування. Вершини мають узгоджено реалізовувати рівність і хеш-код.

## 3. Власна реалізація
* **FileMetadataCache:** словник пов’язує шлях із `FileMetadata`. Реалізовано `Add`, `Get`, `Remove`, `Contains`. Повторне додавання оновлює метадані. Для відсутнього шляху `Get` викидає `KeyNotFoundException`. У демонстрації шлях порівнюється без урахування регістру; це умовна модель для Windows, без читання справжніх файлів і нормалізації шляхів. Хеш задано як демонстраційний рядок.
* **TagManager:** словник зберігає множину тегів кожної статті. `UnionWith` збирає всі унікальні теги, `IntersectWith` знаходить спільні, `ExceptWith` — теги лише першої статті. Регістр тегів ігнорується, пробіли на краях прибираються. Відсутня стаття дає порожню множину. Операції виконуються над копіями, тому не змінюють початкові набори.
* **SearchIndex:** кожне слово пов’язане з множиною ID документів. Текст розбивається на послідовності літер і цифр; регістр і пунктуація не впливають на пошук. `SearchMultiple` перетинає множини: потрібні всі слова. Для відсутнього слова чи запиту без слів результат порожній. Повторне додавання ID замінює старі входження. `Search` повертає копію множини; її створення займає O(k), хоча знаходження запису словника — у середньому O(1). Реалізація навчальна: без пошуку словоформ; зокрема, `C#` розбивається до `C`.

## 4. Порівняльна таблиця
Нехай n — кількість елементів. Для хеш-колекцій наведено середню складність за належного хешування; для додавання — амортизовану.

| Операція | List<T> | Dictionary<TKey, TValue> | HashSet<T> | Коли використовувати |
|---|---|---|---|---|
| Додавання | O(1) у кінець | O(1) | O(1) | Список — послідовність; словник — пари; множина — унікальні значення |
| Пошук за значенням | O(n) | O(n), ContainsValue | O(1) | Множина для частої перевірки значень |
| Пошук за ключем | Не застосовується | O(1) | Не застосовується | Словник для доступу за ідентифікатором |
| Видалення значення / ключа | O(n) | O(1) за ключем | O(1) | Хеш-колекції для частого видалення |
| Перевірка наявності | O(n) | O(1), ContainsKey | O(1), Contains | Залежить від пошуку ключа чи значення |

При зміні розміру додавання може коштувати O(n). Велика кількість колізій погіршує операції словника й множини до O(n). Доступ до списку за індексом — O(1), але це не пошук за довільним ключем.

## 5. Відповіді на контрольні запитання
1. **Переваги generic-колекцій:** перевірка типів під час компіляції, повторне використання коду без ручних приведень; для значущих типів не потрібне пакування в `object`.
2. **Коли обирати Dictionary або HashSet?** Словник потрібний для відповідності «ключ — дані», множина — для унікальних значень, перевірки наявності й операцій об’єднання, перетину та різниці. List зручний, коли важливі порядок, індекси й повтори.
3. **Вплив IEqualityComparer<T>:** задає рівність і хеш-код. Рівні елементи повинні мати однакові хеш-коди. Невдала хеш-функція створює колізії та сповільнює пошук; зміна полів ключа, що визначають його рівність, після додавання порушує коректний пошук. Для всіх пов’язаних множин тегів використано однаковий `OrdinalIgnoreCase`.
4. **Чому інвертований індекс — Dictionary<string, HashSet<int>>?** Словник швидко знаходить слово, а множина зберігає ID без повторів. Перетин множин знаходить документи, які містять усі потрібні слова.
