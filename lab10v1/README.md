## 2. Теоретичні відомості
* **Абстрактний клас:** базовий клас, який не може бути інстанційований напряму. Використовується для побудови ієрархії тісно пов'язаних класів, може містити як абстрактні методи (без реалізації), так і конкретні методи зі спільною логікою.
* **Інтерфейс:** строго визначений контракт поведінки. Використовується для надання однакової функціональності різним, між собою не пов'язаним класам. Один клас може реалізовувати декілька інтерфейсів.
* **Поліморфізм через контракти:** створення колекцій базового типу (інтерфейсу або абстрактного класу) дозволяє однотипно викликати методи для різних об'єктів під час виконання програми.

## 3. Хід виконання роботи

1. **Створення проєкту:** Створено консольний проєкт `lab10v1` у директорії `OOP-Ridchenko`.
2. **Реалізація дженерик-інтерфейсу `IRepository<T>` (Варіант 1):**
   * Визначено контракт з CRUD-операціями (`GetById`, `Add`, `Update`, `Delete`, `GetAll`).
   * Створено клас `User` для демонстрації.
   * Реалізовано клас `InMemoryUserRepository` для роботи з даними у пам'яті.
   * Реалізовано клас `FileUserRepository` для збереження даних у файл `users_db.txt`.
3. **Реалізація абстрактного класу `DocumentProcessor`:**
   * Створено абстрактний клас з конкретним методом логування `LogProcessStart()` та шаблонним методом `Process()`.
   * Реалізовано 3 похідні класи: `PdfDocumentProcessor`, `WordDocumentProcessor`, `ExcelDocumentProcessor` із власною логікою перевизначення (`override`) методів зчитування та обробки.
4. **Тестування у `Main`:**
   * Створено колекцію `List<IRepository<User>>` та продемонстровано збереження користувачів через різні реалізації репозиторію.
   * Створено колекцію `List<DocumentProcessor>` та викликано шаблонний метод `Process()` для кожного типу документів.
5. **Git:** Створено коміт та завантажено проєкт на GitHub.

## 4. Відповіді на контрольні запитання

1. **У чому полягає основна відмінність між абстрактним класом та інтерфейсом:**  
   Абстрактний клас описує об'єктний тип («чим є об'єкт») і може містити стан (поля) та готову реалізацію методів. Інтерфейс описує роль або поведінку («що об'єкт вміє робити») і визначає виключно контракт без збереження стану.

2. **Коли доцільно використовувати абстрактний клас, а коли — інтерфейс? Наведіть приклади:**  
   * **Абстрактний клас:** використовується при побудові тісної ієрархії класів зі спільною логікою (наприклад, `DocumentProcessor` -> `PdfProcessor`, `WordProcessor`).
   * **Інтерфейс:** використовується для надання єдиного контракту різним типам (наприклад, `IRepository<T>` для `InMemoryRepository` та `FileRepository`, або `IPrintable` для `Invoice` та `Photo`).

3. **Чи може клас успадковувати від кількох абстрактних класів? А реалізовывати кілька інтерфейсів:**  
   Клас у C# може успадкувати **лише один** абстрактний (або звичайний) клас через множинне успадкування класичного типу, але може реалізовувати **необмежену кількість** інтерфейсів.

4. **Як абстрактні класи та інтерфейси сприяють поліморфізму та гнучкості архітектури:**  
   Вони дозволяють ослабити зв'язаність коду (Loose Coupling). Клієнтський код залежить від абстракції, а не від конкретної реалізації, що дає змогу легко підміняти деталі реалізації (наприклад, замінити збереження з пам'яті на файл або БД) без зміни логіки всієї програми.
