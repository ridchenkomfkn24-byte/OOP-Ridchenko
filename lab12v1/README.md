## 2. Теоретичні відомості
* **Generics (Узагальнення):** механізм .NET, який дозволяє проектувати класи та методи, відкладаючи специфікацію типів до моменту оголошення коду клієнтом. Це забезпечує сувору типізацію та підвищує швидкодію (відсутність боксингу/унбоксингу).
* **`where` обмеження:** спеціальні правила для Generics, що обмежують типи-аргументи (наприклад, `where T : class, IEntity` гарантує, що `T` є посилальним типом та реалізує інтерфейс `IEntity`).
* **Юніт-тестування (xUnit):** автоматизований підхід перевірки окремих методів за допомогою тверджень (`Assert.Equal`, `Assert.Throws`, `Assert.Null`).

## 4. Відповіді на контрольні запитання

1. **Яка роль where-обмежень у Generics? Наведіть приклади їх використання:**  
   Обмеження `where` вказують компілятору, якими властивостями та методами володіє тип-параметр `T`. Приклади: `where T : struct` (значущий тип), `where T : class` (посилальний тип), `where T : new()` (наявність конструктора без параметрів), `where T : IEntity` (імплементація інтерфейсу).

2. **Навіщо потрібен шаблон IRepository? Які переваги він дає:**  
   Він абстрагує логіку збереження та отримання даних від бізнес-логіки програми. Це дозволяє легко змінювати джерело даних (наприклад, замінити `InMemoryRepository` на `DbRepository` для SQL) без зміни клієнтського коду.

3. **Поясніть, чому юніт-тести є важливими при розробці узагальнених компонентів:**  
   Оскільки узагальнений код працює з різними типами даних, юніт-тести дозволяють переконатися, що логіка репозиторію (CRUD, обробка помилок) залишається стабільною та передбачуваною незалежно від конкретної сутності.

4. **Які проблеми вирішують Generics порівняно з використанням object:**  
   * **Типобезпека:** помилки невідповідності типів виявляються на етапі компіляції, а не під час виконання (Runtime).
   * **Продуктивність:** відсутні витрати ресурсів на пакування та розпакування (boxing/unboxing) для значущих типів.
   * **Чистота коду:** зникає потреба у постійному явному приведенні типів.
